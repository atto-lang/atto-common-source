# Portable signed-i64 source conformance (v1)

**Status: reviewed fixture, not execution evidence.** The corpus `portable-i64.v1.json`
is byte-identical to the source fixture reviewed in `oreslang-source.wasm`
(`contracts/v1/numeric-parity/source-i64-cases.json`, blob
`bbc319c19ecd007109d33592e210091eb267e5a2`).
The fixture's 999 exact bytes are also pinned independently with SHA-256
`39bddbe558ad1c336271f91e6403c4555f2f16a7ed33a3355ee897721b6ab02a`. Both digests must match.

These seven source expressions exercise operator precedence, grouping, checked
signed arithmetic and signed limits. All intermediate values must be within
[-2^63, 2^63-1]. The source `/` operator is *excluded*: Oreslang source division
returns float and must not be compiled as integer division on bootstrap targets.

The corpus validator verifies the exact reviewed Git blob, schema and case IDs,
and uses a distinct, bounded Python AST arithmetic oracle. It **does not** run
a backend. A backend can only claim `executed` after compiling **the same source**
with a real compiler and observing matching outputs or native execution, with
zero skipped cases. Compiler-only checks, host interpreter observations, and
execution of generated bytes must be distinguished in receipts. A fake or
echo-only script cannot be used as evidence.

Run `python3 -m unittest discover -s tests -p test_source_i64_contract.py -v`
and `python3 scripts/verify_source_i64_corpus.py`. Consumers MUST pin
the fixture Git blob and retain fail-closed provenance.
