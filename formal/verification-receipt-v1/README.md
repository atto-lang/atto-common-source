# Verification evidence receipt v1

This experimental receipt is a structural claim format, not an attestation, certificate, or source of authority to merge. Every receipt describes one bounded scope and one independent evidence axis: host-witness, compiler-guest, differential-guest, model-proof, emitted-ir, translation-validation, or implementation-refinement. There is no automatic promotion between axes.

All claims bind repository, commit and tree for the evidence source, the contract and fixture SHA-256 digests, and an explicit scope. Executed compiler claims additionally bind the compiler source identity. Executed claims require toolchain details, a digest of the evidence artifact (for example an archived emitted IR, guest binary, proof script, or diagnostic bundle), transcript digest, run location, nonzero executed step count, and exact pass/fail/skip totals. Proof claims list their trusted assumptions. For a differential claim, the bundle and transcript must identify the comparison oracle or peer implementation and each operand/result; the structural checker does not yet validate that peer independently. A PASS requires nonzero passes, no failures, no skips. A FAIL requires actual failed checks. NOT_EXECUTED and UNSUPPORTED never count outcomes and have no execution artifact or transcript. A runner-admission failure is NOT_EXECUTED, not a compiler failure.

Use Python 3: `python3 formal/verification-receipt-v1/test_receipt.py` and `python3 formal/verification-receipt-v1/receipt.py receipt.json`. The result deliberately always reports authenticated:false. Before accepting evidence, independently retrieve and verify the exact source tree, contract and fixture bytes, artifact and transcript digests, executed steps and actual outcomes. The validator cannot establish cryptographic provenance, expected case completeness, a solver theorem, or machine-code correctness. A future version needs explicit peer identity, case-level receipts, a trusted signature policy, and verified artifact retrieval.
