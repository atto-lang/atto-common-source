# Checked signed multiplication narrowing contract

For an exact signed i128 product of two signed i64 operands, signed overflow is equivalent to the high 64 bits differing from the sign extension of the low 64 bits. The SMT model quantifies over **all** 128-bit product values, not just sampled products. It abstracts multiplication itself; it does not prove a multiplier or compiler lowering. Signed i64 operands have an exact product representable in signed i128.

Run `python3 verify.py --solver /path/to/trusted/z3 --clang clang`. Omitting clang runs only model and replay controls. The model is SHA-256 pinned and must produce the exact reviewed transcript. Z3 4.13.3 required. The locally verified model used the actual libz3 4.13.3.0 via CLI adapter, not the official CLI executable. Results: 4 UNSAT obligations, 3 mutation SAT witnesses, 4 reachability SAT controls; seven malformed replay cases rejected. Clang 17 on Linux compiled the representative LLVM intrinsic and checked-branch IR at O0/O2: each level passed 100,169 signed operand pairs, 56,100 exact results and 44,069 overflow denials that preserved the output slot. Python arbitrary-precision integers serve as independent oracle. These are **not** Atto-emitted IR, guest Error ABI or backend parity receipts.

Applicable implementations can use this narrowing contract for a widened-product path, but independently qualify their production IR and guest artifact. Do not infer the correctness of the compiler, runtime, or a different backend from the model or representative native test. Trusted solver, LLVM intrinsic semantics and host toolchain assumptions remain.
