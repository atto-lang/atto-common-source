# Actor reliability v1

Oreslang actors should be bounded and explicit under load. DATA and CONTROL capacity are finite and separate; send admission, processing completion, timeout, cancellation and delivery are different states. Supervisors use finite restart windows and escalation rather than endless restart loops. Calls use one-shot incarnation-fenced replies. Runtime diagnostics use fixed-size history plus counters, stable categories and monotonic sequence/time, without user message bodies or arbitrary labels. Retries are opt-in, bounded and require idempotency or deduplication. Carrier threads must not block on actor-to-actor work, and hot actors are limited by per-run throughput budgets. Conformance must test saturation, reply/timeout/cancel races, stale incarnations, crash loops, CONTROL during DATA overload, fairness, watchdogs, shutdown races and deterministic fault injection.
